# 雇佣兵系统：设计与实现范围

## 目标玩法

用较高财政成本换取有限的应急兵力、远征专长和集结时间优势。常备军仍是长期主力。兵团身份、等级、装备、规模分开；等级不凭空解锁技术。

最终设计包括：Lv.1–5、5/10/20 营、6/12/24 个月合同、区域有限供给、雇主信用、经验与休整。国家上限建议为 `min(40, max(5, floor(非佣兵常备营数 × 25%)))`。这些是待验证的平衡提案，不是已实现功能。

## 当前版本：0.1.0-dev

首版只交付六档合同的**免费账务模拟**。无实际兵力、军事属性、外籍人口或 AI 招募。原型不需要引入新建筑。

| 参数 | 实现值 |
|---|---|
| 等级 | Lv.1 / 2 / 3，报价倍率 1.25 / 1.50 / 1.80 |
| 规模 | 5 / 10 营，仅作为模拟计价单位 |
| 参考成本 | £400 / 营 / 周，固定演示参数 |
| 入场费 | 四周合同费 |
| 集结 | 四次日志周更新；集结期间不收服役周费 |
| 服役 | 52 次周更新，从集结完成后的下一次更新开始计费 |
| 续约 | 剩余 1–4 周且无欠款时增加 52 周，无新增入场费 |
| 提前解约 | 无欠款且可支付四周赔偿；集结期间同样适用 |
| 到期/欠薪终止 | 进入撤离，不再新增周费；下一次更新关闭模拟合同 |
| 休整 | 合同关闭后再等待八次更新 |
| 初始模拟资金 | 一次性 1,000,000；不随每次签约刷新 |

“周”是日志周脉冲，不保证签约后恰好经过七个整日才第一次推进。52 周是开发版固定时长，不等同于每个日历年的 12 个月。

## 状态机与账务不变量

`空闲 → 集结 → 服役 → 撤离 → 空闲并休整`。

- 一国同时只有一份合同；所有签约、续约和解约效果内部也检查资格，不只依赖按钮状态。
- 报价在签约时快照；合约中途不重算。
- 每次服役更新只出一张账单。若余额不足以支付旧债和本周账单，本周费用进入欠款。
- 恢复资金后支付全部旧债和当周费用，清除连续欠薪计数。
- 连续欠薪六周：增加一次失信记录，进入撤离。终止后保留欠款。
- 旧债未清不能再签约；模拟账户充值和偿债在合同结束后仍可操作。
- 正常到期也不会抹去最后几周形成的债务。
- 无递归延迟事件、无全世界逐日扫描；每份玩家日志仅一个周更新入口。
- 不向 AI 开放，不覆盖原版脚本，不影响驻军模组。

界面在欠薪 1/2/4 周改变状态说明。第二周“暂停补员”是将来军事后端应实施的规则，目前没有部队可供暂停。

## 后续顺序

先验证安全军事后端和实际军费，再开放真实签约；随后实现供给、补员、专长、成长和 AI。不能只修改能力开关就发布正式版。
